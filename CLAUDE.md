# Backend (NestJS)

NestJS 11 + Zod v4 + `nestjs-zod` v5. No `class-validator` / `class-transformer` — Zod is the single source of truth for validation, types, and Swagger schemas.

## Request → response pipeline

Wired once globally in `src/app.module.ts` — never repeat per-controller:

1. `ZodValidationPipe` (APP_PIPE) — parses `@Body()`, `@Query()`, `@Param()` against the Zod DTO. Failure → `ZodValidationException`.
2. Controller handler runs.
3. `ZodSerializerInterceptor` (APP_INTERCEPTOR) — re-validates the return value against the response DTO declared by `@ZodResponse({ type })`.
4. `WebResponseExceptionFilter` (APP_FILTER) — converts any thrown error into the `WebResponse` envelope.

Swagger is generated by `SwaggerModule.createDocument` and post-processed with `cleanupOpenApiDoc()` in `src/main.ts`. The `@nestjs/swagger` CLI plugin is enabled in `nest-cli.json` but is a no-op for Zod DTOs — `@ZodResponse` is what produces their OpenAPI schemas.

## Response envelope

Every successful response: `{ data, paging? }`. Every error: `{ errors: "..." }`. Defined in `src/common/web-response.ts`.

- `WebResponseDto(schema)` — wraps a single-item schema as a DTO class.
- `WebResponseListDto(schema)` — wraps `z.array(schema)` as a DTO class.
- `paginated(items, query, total)` — builds `{ data, paging }` for list endpoints. Don't inline paging math.
- `paginationQuerySchema` — shared `{ limit, offset }` query schema. Extend it for filters: `paginationQuerySchema.extend({ status: z.string().optional() })`.

## Per-resource layout

Four files. Don't split schemas from DTOs.

```
src/<resource>/
  <resource>.dto.ts         schemas + Cat-style type alias + DTO classes
  <resource>.service.ts
  <resource>.controller.ts
  <resource>.module.ts
```

Recipe for `cats.dto.ts`:

```ts
export const CatSchema = z.object({ id: z.uuid(), name: z.string().min(1), /* ... */ });
export type Cat = z.infer<typeof CatSchema>;

export class CreateCatDto extends createZodDto(CatSchema.omit({ id: true })) {}
export class UpdateCatDto extends createZodDto(CatSchema.omit({ id: true }).partial()) {}
export class ListCatsQueryDto extends createZodDto(paginationQuerySchema) {}

export class CatResponseDto extends WebResponseDto(CatSchema) {}
export class CatListResponseDto extends WebResponseListDto(CatSchema) {}
```

Controller pattern — one `@ZodResponse` per route, explicit `WebResponse<T>` return type:

```ts
@Get()
@ZodResponse({ type: CatListResponseDto })
list(@Query() q: ListCatsQueryDto): WebResponse<Cat[]> {
  const { items, total } = this.catsService.list(q.limit, q.offset);
  return paginated(items, q, total);
}

@Get(':id')
@ZodResponse({ type: CatResponseDto })
get(@Param('id', ParseUUIDPipe) id: string): WebResponse<Cat> {
  return { data: this.catsService.get(id) };
}
```

## Conventions and gotchas

- **`import type` for type-only symbols in decorated signatures.** `Cat`, `WebResponse`, etc. used in `@ZodResponse`-decorated method return types must be type-only imports. Otherwise `isolatedModules + emitDecoratorMetadata` emits broken runtime metadata, and you'll see misleading lints like "Unsafe assignment of an error typed value" or compiler error TS1272.
- **`z.uuid()`, not `z.string().uuid()`.** Zod v4 deprecates the chained form.
- **Throw `HttpException` subclasses from services** (e.g. `NotFoundException`). The filter unwraps them into `{ errors: message }` with the correct status code.
- **Validation errors are flattened to a single string** in the `errors` field (`path: message; path: message`). If you ever need structured issues for client localization, change `errors?: string` in `web-response.ts` to accept an array.
- **Don't wrap responses with a custom interceptor.** The envelope is built explicitly in handlers so the OpenAPI schema (`CatResponseDto_Output`, etc.) stays accurate.
- **Don't add `@ApiProperty()` to Zod DTO classes.** The schema is the metadata.
- **Service return types are domain types**, not DTOs. The DTO is the wire contract; the service speaks `Cat`, not `CatResponseDto`.

## Scripts

- `npm run start:dev` — watch mode, http://localhost:3000, Swagger UI at `/api`, raw spec at `/api-json`.
- `npm run build` — `nest build`. Run this to surface TS errors that the IDE may miss.
